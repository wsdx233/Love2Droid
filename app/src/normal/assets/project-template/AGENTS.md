# 游戏开发与验证约束

## 运行环境

- 本项目由 Love2Droid 创建。App 内置的 Android runtime 为 LÖVE 12.0；PRoot 中的 `love-check` 使用固定的 Linux LÖVE 11.5、Xvfb 虚拟屏幕和 Mesa llvmpipe 软件渲染。
- 两个环境并不等价。Linux 11.5 检查通过不能证明 Android 12.0 下行为正确；遇到 12.0 专用 API 或平台差异时，明确报告版本限制，不擅自降级 runtime、修改版本声明或删除功能来换取通过。
- Lua 语法按 LuaJIT 检查，不使用默认 Lua 5.4 的检查结果代替。

## 检查命令

先在 Love2Droid 的“设置 → 环境与扩展组件”中安装“LÖVE 11.5 无界面检查”。首次使用或排查环境问题时执行：

```sh
love-check doctor --frames 3 --timeout 60
```

修改游戏 Lua 代码或资源后，先保存文件，再在项目根目录执行：

```sh
# 只解析源码，不执行 conf.lua、main.lua 或其他模块
love-check check . --syntax-only

# 实际运行，完成 300 次呈现，总超时 30 秒
love-check check . --frames 300 --timeout 30
```

- 命令只读取已保存文件，不会读取编辑器中尚未保存的内容。检查在临时项目副本中执行，使用独立测试存档；不依赖上一次检查留下的存档。
- 无界面检查仍执行真实图形和音频 API。不得伪造 `love.*`、关闭必要模块、跳过出错代码或吞掉异常来制造通过结果。
- 命令缺失、依赖安装失败或无法运行时，如实说明未完成检查，不能声称已验证。

## 结果与边界

- 读取 JSON 的 `status`、`phase`、`error`、日志、实际帧数和 renderer，并结合命令退出码判断。只有命令退出码为 0 且 `status` 为 `passed` 才算对应检查通过。
- 退出码 1 表示检查错误，3 表示游戏提前退出，124 表示超时，130/143 表示取消；这些结果均不算通过。进程仍然存活或没有打印错误，也不等于通过。
- 有限帧检查只能覆盖实际执行到的路径，不能证明整个游戏没有 bug；未进入的关卡、未触发的交互和画面是否符合设计需要另外验证。
- 软件渲染速度不代表手机 GPU 性能；无声运行不验证真实听感。触摸、方向、权限、Android 生命周期及真实画面表现应由用户在真机 Play 验证。
- 汇报时明确区分“LuaJIT 语法通过”“Linux LÖVE 11.5 完成指定帧数”和“Android 真机验证”，不把其中一种替代另一种。
